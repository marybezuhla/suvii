# Формат «Сувій» (`.suvii`) — специфікація

**Версія:** 0.1 (чернетка)
**Статус:** робоча чернетка, може змінюватися без зворотної сумісності до версії 1.0
**Ліцензія тексту специфікації:** [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/deed.uk). Код еталонних інструментів і бібліотек — GPL-3.0-or-later.
**Мови:** українська (ця версія, основна) · [English](SPEC.en.md). Якщо версії розходяться, переважає українська.

Ключові слова **МУСИТЬ**, **НЕ МОЖНА**, **ВАРТО**, **МОЖНА** вживаються в значенні RFC 2119 (MUST, MUST NOT, SHOULD, MAY).

---

## 1. Що це і навіщо

Сувій — відкритий формат для **офлайн-колекцій текстових документів**, які **можна оновлювати**: законодавство, словники, довідники, енциклопедії.

Цілі:

1. **Оновлюваність.** Колекцію можна оновити невеликою **латкою**, не завантажуючи все наново.
2. **Справжність.** Кожна колекція й кожна латка підписані видавцем. Читалка перевіряє, що текст ніхто не змінив.
3. **Компактність.** Тексти стиснуті zstd, можливо зі спільним словником.
4. **Пошук без мережі.** Повнотекстовий індекс у самому файлі.
5. **Простота і відкритість.** Файл — звичайна база SQLite 3 з описаною тут схемою. Його можна відкрити будь-яким інструментом для SQLite.
6. **Сумісність.** Колекцію можна експортувати в ZIM для Kiwix (див. розділ 13).

Поза межами версії 0.1: зображення й інші медіа, історія редакцій, ротація ключів, шифрування. Див. розділ 14.

## 2. Терміни

| Термін | Значення |
|---|---|
| **Колекція** | Набір документів з одним ідентифікатором (`collection.id`) і одним видавцем. |
| **Сувій** | Файл `.suvii`. Буває двох видів: **основа** або **латка**. |
| **Основа** (`base`) | Повний стан колекції на певний **номер стану** (`seq`). |
| **Латка** (`patch`) | Зміни між двома номерами стану: нові й змінені документи та видалені шляхи. |
| **Номер стану** (`seq`) | Ціле число ≥ 1, що зростає з кожною зміною колекції. |
| **Шлях** (`path`) | Сталий ідентифікатор документа в колекції, наприклад `laws/254к/96-вр`. |
| **Видавець** | Той, хто підписує сувої колекції своїм ключем ed25519. |
| **Читалка** | Програма, що відкриває сувої. |

## 3. Файл

- Файл **МУСИТЬ** бути базою даних SQLite 3.
- `PRAGMA application_id` **МУСИТЬ** дорівнювати `0x53555649` (ASCII `SUVI`, десяткове `1398101577`).
- `PRAGMA user_version` **МУСИТЬ** дорівнювати основному номеру версії формату. Для версій 0.x це `0`, для 1.x — `1`.
- Повна версія формату записана в `meta` під ключем `suvii.format` (наприклад, `0.1`).
- Розширення файлу: `.suvii`. Тип MIME до реєстрації: `application/x-suvii`.
- Файл для поширення **ВАРТО** зберігати з `journal_mode=DELETE`, після `VACUUM`, без файлів `-wal`/`-journal` поруч.
- Рекомендована назва файлу: `<колекція>-<мова>-<РРРР-ММ-ДД>.suvii` для основи, `<колекція>-<мова>-<from_seq>-<to_seq>.patch.suvii` для латки.

## 4. Схема

Усі текстові значення — UTF-8 у нормалізації **NFC**. Усі дати й час — RFC 3339 в UTC (`2026-11-04T12:00:00Z`), дати без часу — `РРРР-ММ-ДД`.

```sql
-- Метадані колекції
CREATE TABLE meta (
  key   TEXT PRIMARY KEY NOT NULL,
  value TEXT NOT NULL
) WITHOUT ROWID;

-- Документи
CREATE TABLE docs (
  id       INTEGER PRIMARY KEY,         -- локальний номер, різний у різних файлах
  path     TEXT    NOT NULL UNIQUE,     -- сталий ідентифікатор (розділ 5)
  title    TEXT    NOT NULL,
  mime     TEXT    NOT NULL,            -- 'text/plain' або 'text/html' (розділ 6)
  size     INTEGER NOT NULL,            -- довжина тексту без стиснення, у байтах
  updated  TEXT    NOT NULL,            -- коли документ востаннє змінено (RFC 3339)
  hash     BLOB    NOT NULL             -- 32 байти, розділ 9.1
);

-- Частини тексту документа
CREATE TABLE chunks (
  doc_id   INTEGER NOT NULL REFERENCES docs(id) ON DELETE CASCADE,
  n        INTEGER NOT NULL,            -- 0, 1, 2, … без пропусків
  dict_id  INTEGER REFERENCES dicts(id),-- NULL = без словника
  data     BLOB    NOT NULL,            -- кадр zstd
  PRIMARY KEY (doc_id, n)
) WITHOUT ROWID;

-- Словники zstd
CREATE TABLE dicts (
  id   INTEGER PRIMARY KEY,
  data BLOB NOT NULL
);

-- Поля документа для фільтрів (вид, статус, дата тощо)
CREATE TABLE facets (
  doc_id INTEGER NOT NULL REFERENCES docs(id) ON DELETE CASCADE,
  key    TEXT    NOT NULL,
  value  TEXT    NOT NULL,
  PRIMARY KEY (doc_id, key, value)
) WITHOUT ROWID;
CREATE INDEX facets_kv ON facets(key, value);

-- Зміст документа (розділи, статті)
CREATE TABLE toc (
  doc_id INTEGER NOT NULL REFERENCES docs(id) ON DELETE CASCADE,
  ord    INTEGER NOT NULL,              -- порядок, 0, 1, 2, …
  level  INTEGER NOT NULL,              -- 1 = верхній рівень
  anchor TEXT    NOT NULL,              -- значення атрибута id у тексті
  title  TEXT    NOT NULL,
  PRIMARY KEY (doc_id, ord)
) WITHOUT ROWID;

-- Зв'язки між документами
CREATE TABLE links (
  doc_id   INTEGER NOT NULL REFERENCES docs(id) ON DELETE CASCADE,
  kind     TEXT    NOT NULL,            -- наприклад 'amends', 'amended_by', 'refers'
  target   TEXT    NOT NULL,            -- шлях цільового документа (може бути відсутній у колекції)
  anchor   TEXT    NOT NULL DEFAULT '',
  PRIMARY KEY (doc_id, kind, target, anchor)
) WITHOUT ROWID;
CREATE INDEX links_target ON links(target);

-- Видалені шляхи (лише в латках)
CREATE TABLE tombstones (
  path    TEXT PRIMARY KEY NOT NULL,
  deleted TEXT NOT NULL
) WITHOUT ROWID;

-- Повнотекстовий пошук (необов'язковий, розділ 8)
CREATE VIRTUAL TABLE fts USING fts5(
  title, body,
  content = '',
  contentless_delete = 1,
  tokenize = 'unicode61 remove_diacritics 0'
);
-- rowid у fts = docs.id
```

- У файлі **НЕ МОЖНА** мати тригерів і подань (views). Інші таблиці й індекси **МОЖНА** додавати. Читалка **МУСИТЬ** ігнорувати невідомі таблиці (див. розділ 10).
- У латці таблиця `tombstones` **МОЖЕ** бути непорожньою. В основі вона **МУСИТЬ** бути порожньою.

### 4.1. Обов'язкові ключі `meta`

| Ключ | Приклад | Опис |
|---|---|---|
| `suvii.format` | `0.1` | Версія формату. |
| `suvii.kind` | `base` або `patch` | Вид сувою. |
| `collection.id` | `6f0d…` | UUID колекції (36 символів, малими літерами). Однаковий для всіх основ і латок колекції. |
| `collection.title` | `Законодавство України` | Назва. МОЖНА додати перекладені: `collection.title.en`. |
| `collection.language` | `uk` | Мова документів (BCP 47). |
| `collection.publisher` | `Chynnist` | Видавець. |
| `collection.fields` | JSON, розділ 7 | Опис полів `facets`. |
| `state.seq` | `42` | Номер стану основи. У латці — номер стану **після** застосування. |
| `state.created` | `2026-11-04T03:00:00Z` | Коли створено цей сувій. |
| `state.source_date` | `2026-11-03` | Дата, станом на яку зібрано дані. |
| `sign.alg` | `ed25519` | Алгоритм підпису. |
| `sign.key` | base64 | Публічний ключ видавця (32 байти). |
| `sign.sig` | base64 | Підпис (64 байти), розділ 9. |

Лише в латках:

| Ключ | Опис |
|---|---|
| `patch.from_seq` | Номер стану, до якого застосовується латка. |
| `patch.to_seq` | Номер стану після застосування (дорівнює `state.seq`). |
| `patch.state_root` | Очікуваний корінь стану після застосування, hex (розділ 9.2). |
| `patch.base_sig` | Підпис основи, яка вийде після застосування, base64 (розділ 9.4). |

Необов'язкові: `collection.description`, `collection.homepage`, `collection.license` (ліцензія даних), `collection.source` (звідки дані), `collection.icon` (SVG, не більше 64 КБ).

## 5. Шляхи

- Шлях — рядок UTF-8 у NFC, від 1 до 1024 байтів.
- Складається з сегментів, розділених `/`. Сегмент не порожній і не дорівнює `.` чи `..`.
- Без початкового й кінцевого `/`, без керувальних символів (U+0000–U+001F, U+007F), без `\`, `?`, `#`.
- Шлях **МУСИТЬ** бути сталим: той самий документ у наступних станах колекції має той самий шлях.

## 6. Текст документа

### 6.1. Стиснення й частини

- Текст документа розбито на частини (`chunks`). Кожна частина — окремий кадр zstd, який розпаковується самостійно (з відповідним словником, якщо `dict_id` не NULL).
- Розпакована частина **НЕ МОЖЕ** перевищувати 1 МіБ (1 048 576 байтів), стиснута — 256 КіБ (262 144 байти). Межа потрібна, бо Android не читає рядків бази, більших за 2 МБ.
- Частини йдуть по порядку `n = 0, 1, 2, …`. Текст документа — конкатенація розпакованих частин. Межа частини **ВАРТО** проходити між елементами HTML (але читалка МУСИТЬ правильно обробляти будь-яку межу, бо текст склеюється перед показом).
- Сума довжин розпакованих частин **МУСИТЬ** дорівнювати `docs.size`.
- Документ **НЕ МОЖЕ** бути більшим за 64 МіБ.

### 6.2. Види тексту

- `text/plain` — звичайний текст, рядки розділені `\n`.
- `text/html` — фрагмент HTML (без `<html>`, `<head>`, `<body>`) лише з **безпечної підмножини**:
  - елементи: `p br hr h1 h2 h3 h4 h5 h6 div span blockquote pre code ul ol li dl dt dd table thead tbody tfoot tr th td caption b strong i em u s sub sup small a`;
  - атрибути: `id` (будь-який елемент), `lang`, `dir`, `colspan`, `rowspan`, `href` (лише в `a`), `class` (лише значення з префіксом `suvii-`);
  - `href` **МУСИТЬ** бути одним із: `#якір`, `suvii:<шлях>` або `suvii:<шлях>#якір` (посилання всередині колекції), `https://…` (зовнішнє).
  - **НЕ МОЖНА:** `script`, `style`, атрибути `on*`, `style`, `src`, будь-які завантаження з мережі.
- Читалка **МУСИТЬ** відкидати або вичищати все поза цією підмножиною, навіть якщо підпис правильний. **ВАРТО** питати людину перед відкриттям зовнішнього посилання.

## 7. Поля (`facets`)

`collection.fields` — об'єкт JSON, що описує ключі з таблиці `facets`:

```json
{
  "kind":   {"type": "enum", "title": {"uk": "Вид", "en": "Type"},
             "values": {"law": {"uk": "Закон"}, "code": {"uk": "Кодекс"}, "resolution": {"uk": "Постанова"}}},
  "number": {"type": "text", "title": {"uk": "Номер"}},
  "status": {"type": "enum", "title": {"uk": "Стан"},
             "values": {"in_force": {"uk": "Чинний"}, "repealed": {"uk": "Втратив чинність"}}},
  "adopted":{"type": "date", "title": {"uk": "Дата ухвалення"}},
  "edition":{"type": "date", "title": {"uk": "Редакція від"}},
  "issuer": {"type": "text", "title": {"uk": "Видавник"}, "multi": true}
}
```

- Типи: `text`, `int` (десяткове ціле, не більше 18 цифр), `date` (`РРРР-ММ-ДД`, роки 0001–9999), `bool` (`0`/`1`), `enum` (значення лише з `values`).
- `multi: true` дозволяє кілька значень одного ключа в документа.
- Значення в `facets` — завжди текст у вказаному форматі.

## 8. Пошук

- Таблиця `fts` необов'язкова. Якщо вона є, `rowid` **МУСИТЬ** дорівнювати `docs.id`, а `body` містить текст документа без розмітки HTML.
- Якщо її немає (наприклад, щоб зменшити файл), читалка **МОЖЕ** побудувати індекс сама.
- Індекс «без вмісту» (`content=''`) не можна перенести з одного файлу в інший, тому латка **НЕ МІСТИТЬ** `fts`. Застосовуючи латку, читалка сама індексує її документи (розділ 12).

## 9. Цілісність і підпис

Хеш: SHA-256. Підпис: ed25519 (RFC 8032), чистий, без попереднього хешування.

Позначення: `u32(x)` і `u64(x)` — ціле без знака big-endian на 4 і 8 байтів; `str(s)` = `u32(довжина у байтах) ‖ байти UTF-8`; `‖` — конкатенація.

### 9.1. Хеш документа

```
doc_hash = SHA-256(
  "suvii-doc-1\n"
  ‖ str(path) ‖ str(title) ‖ str(mime) ‖ str(updated)
  ‖ u32(кількість facets) ‖ для кожного (key, value), впорядкованих за байтами key, потім value: str(key) ‖ str(value)
  ‖ u32(кількість toc)    ‖ для кожного за ord: u32(level) ‖ str(anchor) ‖ str(title)
  ‖ u32(кількість links)  ‖ для кожного, впорядкованих за байтами kind, target, anchor: str(kind) ‖ str(target) ‖ str(anchor)
  ‖ u64(size) ‖ розпакований текст
)
```

Значення записано в `docs.hash`. Стиснення й поділ на частини на хеш не впливають.

### 9.2. Корінь стану

```
state_root = SHA-256(
  "suvii-state-1\n"
  ‖ 16 байтів collection.id ‖ u64(state.seq) ‖ u64(кількість документів)
  ‖ для кожного документа, впорядкованого за байтами path: str(path) ‖ doc_hash
)
```

Щоб обчислити корінь, достатньо прочитати `path` і `hash`, тексти розпаковувати не потрібно.

### 9.3. Хеш метаданих

```
meta_hash = SHA-256("suvii-meta-1\n" ‖ для кожного ключа meta, крім ключів з префіксом "sign.", впорядкованих за байтами: str(key) ‖ str(value))
```

### 9.4. Що підписується

Основа:
```
повідомлення = "suvii-sig-1\nbase\n" ‖ meta_hash ‖ state_root
```

Латка:
```
patch_root = SHA-256("suvii-patch-1\n"
  ‖ 16 байтів collection.id ‖ u64(from_seq) ‖ u64(to_seq)
  ‖ u64(кількість документів) ‖ для кожного за байтами path: str(path) ‖ doc_hash
  ‖ u64(кількість tombstones) ‖ для кожного за байтами path: str(path))

повідомлення = "suvii-sig-1\npatch\n" ‖ meta_hash ‖ patch_root ‖ очікуваний state_root після застосування
```

Крім того, латка несе в `patch.base_sig` **готовий підпис основи**, яка вийде після застосування: це підпис повідомлення для основи (вище), де `meta_hash` обчислено з метаданих латки без ключів `patch.*` і зі значенням `suvii.kind = base`. Завдяки цьому оновлена основа перевіряється так само, як щойно завантажена, і самі латки після застосування зберігати не треба.

`meta_hash` латки обчислюється з усіх її ключів, крім `sign.*`; ключ `patch.base_sig` теж не входить до нього.

### 9.5. Перевірка

- Читалка **МУСИТЬ** перевіряти підпис ключем, якому вона довіряє (наприклад, вбудованим у застосунок), а не лише ключем із `sign.key`. Ключ із файлу корисний лише для показу й для інструментів.
- При відкритті основи читалка **МУСИТЬ** обчислити `state_root` і перевірити підпис.
- Перед показом документа читалка **ВАРТО** перевірити його `doc_hash`. Якщо хеш не збігається, документ пошкоджено: його не можна показувати як справжній.

## 10. Безпечне відкриття

Сувій — файл з чужих рук. Читалка **МУСИТЬ**:

1. Перевірити `application_id` і `user_version`. Якщо основна версія більша за підтримувану, відмовити з поясненням «потрібна новіша версія програми».
2. Відкривати з `PRAGMA trusted_schema=OFF` і в захисному режимі (`SQLITE_DBCONFIG_DEFENSIVE`), а файл для поширення — лише для читання, поки не перевірено підпис.
3. Перевірити `sqlite_schema`: немає тригерів і подань; обов'язкові таблиці мають саме ту схему, що описана тут.
4. Перевірити межі з розділу 11 **до** того, як виділяти пам'ять під дані.
5. Перевірити підпис (розділ 9.5).
6. Обробляти будь-яку помилку як «файл пошкоджено», без падіння і без сирих текстів помилок.

## 11. Межі

| Що | Межа |
|---|---|
| Шлях | 1024 байти |
| Назва документа | 4096 байтів |
| `mime`, `updated`, ключ і значення `facets`, якір, `kind`, `target` | 1024 байти кожне |
| Назва в `toc` | 4096 байтів |
| Кількість `facets`, `toc`, `links` на документ | 10 000 кожного |
| Частина: стиснута / розпакована | 256 КіБ / 1 МіБ |
| Документ розпакований | 64 МіБ |
| Словник zstd | 1 МіБ, не більше 256 словників |
| Значення в `meta` | 1 МіБ (крім `collection.icon` — 64 КБ) |
| Кількість документів | 2³¹ − 1 |
| `state.seq` | 1 … 2⁶³ − 1 |

## 12. Латки: як застосовувати

Латку можна застосувати до основи, якщо:

- `collection.id` збігаються;
- `patch.from_seq` дорівнює `state.seq` основи (латки можуть бути **накопичувальними**: від будь-якого старішого стану до нового; читалка обирає найкоротший ланцюжок);
- підпис латки правильний.

Застосування — **одна транзакція**:

1. Для кожного шляху з `tombstones` видалити документ із цим шляхом (разом з частинами, полями, змістом, зв'язками і записом у `fts`).
2. Для кожного документа латки: видалити документ із тим самим шляхом, якщо він є, і вставити новий з усіма частинами, полями, змістом і зв'язками. Якщо в основі є `fts`, додати запис для нового документа, обчисливши текст без розмітки. Номери `id`, як і номери словників, призначаються заново.
3. Скопіювати потрібні словники з латки (з новими номерами).
4. Замінити `meta` основи метаданими латки без ключів `patch.*`, зі значенням `suvii.kind = base` і з `sign.sig = patch.base_sig`.
5. Обчислити `state_root` і порівняти з `patch.state_root`, а також перевірити підпис оновленої основи (розділ 9.5). Якщо щось не збігається — **скасувати транзакцію**.

Результат логічно ідентичний основі з номером `to_seq`, яку видав би видавець.

Словники, на які більше не посилається жодна частина, **МОЖНА** видалити.

## 13. Експорт у ZIM

Інструмент `suvii export-zim` перетворює основу на стандартний ZIM:

- кожен документ стає записом `A/<шлях>` (HTML; `text/plain` загортається в `<pre>`), заголовок — `title`;
- посилання `suvii:<шлях>#якір` перетворюються на відносні посилання ZIM;
- `facets` і `toc` додаються як невидима таблиця на початку сторінки документа та як окрема сторінка-покажчик;
- метадані ZIM (`Title`, `Language`, `Creator`, `Publisher`, `Date`, `Description`) беруться з `meta`;
- у ZIM-файлі зберігаються `collection.id` і `state.seq`, щоб було видно, з якого стану його зроблено.

ZIM — лише знімок для читання: оновлюється сам сувій, а ZIM створюється наново.

## 14. Майбутнє (не у версії 0.1)

- **Медіа:** таблиця `files` для зображень і вкладень (потрібно для Вікіпедії).
- **Історія редакцій:** кілька редакцій одного документа з датою, щоб показувати «як було на певну дату».
- **Ротація ключа видавця:** підписаний перехід на новий ключ.
- **Часткові колекції:** підписаний список шляхів, що дозволяє мати на телефоні лише частину колекції.
- **Розбиття на кілька файлів** для дуже великих колекцій.

## 15. Сумісність версій

- Версії `0.x` — чернетки, сумісність між ними не гарантується.
- Починаючи з `1.0`: зміна молодшої версії (`1.1`, `1.2`) лише **додає** необов'язкові таблиці, колонки чи ключі `meta`; читалка версії `1.0` відкриває файли `1.x`, ігноруючи невідоме. Зміна основної версії (`2.0`) змінює `user_version`.

## Додаток А. Приклад: законодавство України

- `collection.id`: фіксований UUID колекції «Чинність».
- Шлях: `laws/<номер документа на zakon.rada.gov.ua>` малими літерами, наприклад `laws/254к/96-вр` (Конституція).
- `facets`: `kind` (вид, кілька значень: `law`, `code_of_ukraine`, `constitution`…), `status` (стан: `in_force`, `repealed`…), `number` (номер документа), `edition` (дата редакції). Згодом: `adopted`, `issuer`.
- `toc`: розділ — рівень 1, глава — 2, стаття — 3. Якір — той самий, що на сайті Ради, наприклад `n4188`: тоді посилання між документами (`suvii:laws/2341-14#n12`) ведуть туди ж, куди й на сайті.
- Класи: `suvii-center`, `suvii-right` (вирівнювання), `suvii-note` (редакційні примітки `{…}`).
- `links`: згодом `amends` / `amended_by` — зміни між документами.
- `collection.source`: `https://data.rada.gov.ua` (портал відкритих даних Верховної Ради України).
- `collection.license`: умови порталу відкритих даних: вільне використання та поширення з посиланням на джерело.
